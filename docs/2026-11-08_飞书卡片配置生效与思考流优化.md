# 飞书 CardKit 2.0 配置生效与思考流深度重构记录 (2026-11-08)

## 1. 问题根因追溯与底层真相

### 问题 1：新建话题 `/new` 模型与思考模式形同虚设
- **根本原因 1（SessionStore 静默丢弃）**：新建话题时，SQLite 与内存路由表尚无新 `session_key` 对应的 `SessionEntry`，直接调用 `store.set_model_override()` 会触发 `if entry is None: return`，导致持久化写入被静默忽略。
- **根本原因 2（运行时优先读取 `_session_state`）**：准备 turn 时 `run_turn_prepare` 最先检查的是 `gw._session_state(skey).conversation.model_override`，单纯写入 legacy dict `_session_model_overrides` 无法生效。
- **根本原因 3（表单缺少渠道联动与未选兜底）**：飞书卡片表单内静态下拉框不会触发客户端与服务端网络联动。用户在平铺列表中难以精确选择，未选时字段为空，后端 `if model:` 直接跳过注入，退回全局默认 `hy4free`。

### 问题 2：思考内容流式输出跳动与“滑块”设想
- **飞书规范硬限制**：飞书 Card 2.0 原生组件不支持自定义 CSS 或固定像素高度的滚动容器（不支持 `overflow-y: scroll`）；普通代码块（````thought````）会随文本向下无限撑大卡片，不具备纵向滚动滑块。
- **跳行抖动根因**：带动态数字的省略提示（如 `（已省略前 N 行）`）字数与高度突变，触发飞书客户端激进重排与上下颠簸。

## 2. 落地解决方案

1. **渠道按钮组即时联动筛选**：
   - 卡片顶部提供整洁的渠道按钮组（Antigravity、阿里云百炼、WorkBuddy、讯飞星火、Nous Portal）；
   - 点击即触发 `card.action.trigger`（`action_type="select_channel"`），卡片原地刷新为所选渠道专属的模型下拉框，并在未选时自动绑定该渠道默认旗舰模型。
2. **四重坚固注入机制**：
   - `gw.session_store.get_or_create_session(src)` 先行落库创建 entry；
   - `gw.session_store.set_model_override()` 持久化覆盖；
   - `gw._session_state(skey).conversation.model_override` 与 `reasoning_override` 内存直注；
   - `gw._evict_cached_agent(skey)` 驱逐旧实例。
3. **恒定单行视窗防抖 + 结尾全量归档**：
   - 流式阶段：超过 360 字符后固定提取最新切片（约 6~7 行），顶部采用恒定高度单行提示 `<font color='grey'>▲ 早期思考已向上收起 · 正在最新推理…</font>`，高度锁定，彻底杜绝跳行；
   - 状态行（`status_line`）全程呈现 `🧠 思考中… (已推理 N 字) · ⏱️ Ns`；
   - 收尾阶段：恢复 100% 全量未截断的完整思考全文，归档入折叠面板供随时展开回溯。

## 4. 解决 10 分钟卡片误封与长任务自动续期机制 (2026-11-08)

### 根因深度剖析
1. **硬编码闲置定时器误杀**：原代码设定 `IDLE_FINALIZE_SECS = 600`（10 分钟）。若底层工具（如计算化学、代码编译、大规模检索）单步执行耗时较长，中途无事件重置定时器，卡片在第 10 分钟整会被 `_auto_finalize()` 强行封卡为完成态（正文为“本轮无最终答复”），并从活跃注册表 `_ACTIVE` 抹除。
2. **答复脱钩与内容丢弃**：封卡后 `ck.finalized == True`，当 Agent 在第 11+ 分钟返回最终答复时，`get_active()` 返回 None，导致最终结论被完全吞没丢弃。
3. **飞书 CardKit 流式限制**：飞书服务端对单个卡片的 `streaming_mode` 有生命周期硬限制（约 10~15 分钟），超时后关闭打字机接口。

### 落地解决方案
1. **兜底超时放宽至 1 小时**：`IDLE_FINALIZE_SECS = 3600`，杜绝长任务中途被误判为死卡。
2. **轻量自动心跳续期（Heartbeat Keep-Alive）**：卡片创建后启动 30 秒后台轻量定时器，自动在状态行刷新已运行时间（如 `⏳ 正在处理中… · ⏱️ 12m 30s`），并自动调用 `_touch()` 持续重置超时钟，卡片全程保持鲜活。
3. **最近卡片归档与 PATCH 覆盖**：新增 `_RECENT_CARDS` 归档缓存，即便卡片意外脱钩，最终答复到达时仍能通过 `PATCH /im/v1/messages/{message_id}` 进行静默全量覆盖，确保用户的回答 100% 必达。
